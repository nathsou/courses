Every collector in Part VI starts the same way: find the roots, the pointers held in variables, and trace from there. So far the course’s VM has simply known which of its stack slots hold pointers. A real compiler has to work for that knowledge, and the work shapes both the compiler and the collector. There are two broad answers. A **precise** collector is told, for every stack slot it might find, whether it holds a pointer. A **conservative** collector is told nothing, and treats anything that looks like a pointer as one.

## Precise: stack maps and safepoints

A compiler knows the type of every variable and every intermediate value, so it can write down, for a given instruction, which slots of the frame hold pointers. Doing that for *every* instruction would be enormous and pointless. Instead the compiler picks **safepoints**, the only places where a collection may begin, and records a **stack map** for each :cite[jones2023]. A collection can only start at an allocation, at a call (because the callee might allocate), or wherever the program agrees to stop, such as the back-edge of a loop, so that a long loop does not hold up a collection indefinitely.

:::stack-map-viewer{n="24.1"}
```mote

  let n = new Node { value: v, next: head }
  return n
}

fn main() {
  var list: Node? = null
  for i in 0..3 {
    list = push(list, i * 10)
  }
  print(list.value)
}
```
Mote compiles to a stack machine; ● marks the safepoints. Click one to see the frame a collector would scan there.
:::

Look at the `NEW` in `push`. While the new node is being allocated, `head` has already been pushed onto the operand stack as an argument to the constructor; if the allocation triggers a collection, that temporary is a root, and the stack map says so. A compiler that forgot the temporaries would let the collector free the list out from under the program. Deciding which slots hold *live* pointers at each safepoint is a liveness analysis, the same analysis a register allocator runs.

:::bridge{course=compiler-backends chapter=liveness title="SSA to Silicon, chapter 11: Liveness analysis"}
How a compiler computes, at every point of a function, which values will be used again. A garbage collector’s stack maps need the same answer for pointers.
:::

When the code is generated by a compiler that cannot produce stack maps, for example a compiler that emits C, there is a portable alternative: keep the pointer variables in a separate **shadow stack** that the generated code maintains explicitly, at some cost on every call :cite[henderson2002].

## Conservative: if it looks like a pointer

Hans Boehm and Mark Weiser asked what a collector could do with no help at all, in an “uncooperative environment” such as a C program :cite[boehm1988]. Their answer: scan every word of the stacks, registers and globals, and treat any word whose value falls inside an allocated object as a pointer to it. A word that happens to be an integer with the right value keeps an object alive by accident, but nothing that really is a pointer is ever missed. The result is a garbage collector that “can be used as a garbage collecting replacement for C malloc or C++ new” :cite[boehm-gc].

::conservative-scan

The cost of guessing is **false retention**: memory kept alive by a number that only looks like a pointer. Usually a little; occasionally, as in the figure, a whole chain of objects reached from the falsely retained one. And because the collector cannot know which words are really pointers, it cannot change them, so it cannot move the objects they point to: a conservatively found root **pins** its object in place. Collectors that scan the stack conservatively but the heap precisely can still move every object that is reachable only from the heap :cite[jones2023].

solution: |
  import { GcHeap } from '@mm/gc';

  /**
   * A conservative root scanner. `words` are the raw contents of the stack: some are pointers, most are not, and
   * nothing says which. Return the objects (by their start address, each once) that some word points into, including
   * pointers into the middle of an object. Ignore words that point outside the heap or into a freed object.
   */
  export function conservativeRoots(heap: GcHeap, words: number[]): number[] {
    // Object start addresses, in order, for a binary search.
    const starts = [...heap.objects()];
    const found = new Set<number>();
    for (const w of words) {
      if (w < heap.mem.base || w >= heap.top) continue;
      let lo = 0;
      let hi = starts.length - 1;
      while (lo < hi) {
        const mid = (lo + hi + 1) >> 1;
        if (starts[mid]! <= w) lo = mid;
        else hi = mid - 1;
      }
      const o = starts[lo]!;
      if (w < o + heap.size(o) && !heap.isFree(o)) found.add(o);
    }
    return [...found];
  }
tests: |
  import { test, expect } from '@mm/test';
  import { GcHeap } from '@mm/gc';
  import { conservativeRoots } from './solution';

  function heapOf(n: number) {
    const heap = new GcHeap({ bytes: 1 << 20, roots: 1 });
    const small = heap.addType('Small', 1, 0);
    const big = heap.addType('Big', 2, 5);
    const objs = Array.from({ length: n }, (_, i) => heap.alloc(i % 3 ? small : big));
    return { heap, objs };
  }
  const sorted = (xs: number[]) => [...xs].sort((a, b) => a - b);

  test('exact pointers find their objects, each once', () => {
    const { heap, objs } = heapOf(20);
    expect(sorted(conservativeRoots(heap, [objs[3]!, objs[7]!, objs[3]!]))).toEqual(sorted([objs[3]!, objs[7]!]));
  });
  test('a pointer into the middle of an object finds the object', () => {
    const { heap, objs } = heapOf(20);
    expect(conservativeRoots(heap, [objs[6]! + 24])).toEqual([objs[6]!]);
    expect(conservativeRoots(heap, [objs[7]! - 8])).toEqual([objs[6]!]);
  });
  test('numbers outside the heap, and pointers into freed objects, are ignored', () => {
    const { heap, objs } = heapOf(20);
    heap.free(objs[5]!);
    expect(conservativeRoots(heap, [0, 1, 42, heap.mem.base - 8, heap.top, heap.top + 100, objs[5]!, objs[5]! + 8])).toEqual([]);
  });
  test('many objects and many words', () => {
    const { heap, objs } = heapOf(5000);
    const words = objs.filter((_, i) => i % 7 === 0).map((o) => o + 8);
    expect(sorted(conservativeRoots(heap, [...words, 3, 5, 7]))).toEqual(sorted(objs.filter((_, i) => i % 7 === 0)));
  });

:::key
A collector’s roots are the pointers in the stacks, registers and globals. A **precise** collector learns which slots hold pointers from **stack maps** that the compiler records at **safepoints**, the only places a collection can start; temporaries count. A **conservative** collector treats every word that falls inside an object as a pointer: it needs no help from the compiler, but suffers **false retention**, and must **pin** the objects it finds that way.
:::

:::whofrees
The collector, but only for objects it is sure about. A precise collector frees exactly the unreachable objects; a conservative one sometimes keeps a few extra alive, because it cannot prove that a number is only a number.
:::
